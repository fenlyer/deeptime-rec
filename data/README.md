## 三、反馈强度 α_r 与「行为类型」的关系

V9 3.3.1 表3-1 **只按评分定权**，不再出现「行为类型」作为论证依据：

| 评分 | α_r | 论文依据（V9 3.3.1 表3-1） |
|---|---|---|
| 5 | 3.0 | 强烈满意，偏好确定性最强 |
| 4 | 1.5 | 基本满意，偏好强度次之 |
| 3 | 1.0 | 中性基准 |
| 1~2 | 0.1 | 负面，权重极低，仅供冷启动补充图连通性 |

| 数据集 | 原始字段 | α_r 来源 |
|---|---|---|
| IS / TH / OP | `rating` 1~5 | 查表3-1 |
| AJ | `action_type` 0/1/2/3 | `click=1.0 / cart=1.2 / buy=3.0 / collect=1.5`（与表3-1 同构，因 V9 只给评分档，AJ 的 action_type→α 需在正文交代一句） |

- 统一边权函数（V9 式 3-1）：`w(u,i) = α_r · exp(-λ·(T_now − t)/T)`，`T=86400` 秒、`λ=0.001`、
  `T_now = 数据集最大时间戳`。多行为同一对时**权重求和**（AJ 唯一受影响）。
- **Amazon 侧恒无 `cart`**（`cart.count = 0`），α=1.2 档位只在 AJ 与线上系统出现。
- `train/val/test.csv` 里的 `behavior` 列（buy/collect/click/show）是**派生伪标签**，
  保留它只为与 AJ 对齐、兼容旧代码；V9 正文已不再按「行为类型」论证，
  **不要在正文或表格里把 behavior 当作论文口径**。

## 六、口径注意事项（与 V9 正文直接相关）

1. **统计单位是「用户-物品对」，不是行为记录。** AJ 有 3,533 万条行为记录、
   3,088 万个对；按行计数会把稀疏度和人均交互算高。所有核验脚本先
   `drop_duplicates(['user_id','item_id'])`。**`train.csv` 行数 ≠ 对数**，尤其 AJ。
2. **LOO 的划分单位是对，不是行为记录。** 同一 `(user,item)` 对的全部行为记录始终
   落在同一侧（`temporal_split` 以对为单位取 `max(timestamp)` 排序，并列时按
   `item_id` 字典序打破平局）。因此每位用户在 test 中恰好 1 对（四数据集均已验证）。
   自建划分与 Amazon 官方 `last_out` 测试集重合率：IS 99.998%、TH 99.999%、OP 99.999%。
3. **训练集口径 vs 全量口径。** 5-core 保证全量 ≥5 对，但 LOO 切走 test+val 后，
   全量 5~6 对的用户在训练集只剩 3~4 对，故 V9 3.5.5 的超冷启动层（0~4 条）占 53.7%。
   这不是数据错误；表3-11 已注明「训练集口径」。自 2026-11-25 起，3.1 的画像指标
   也统一为训练集口径（见第 6 条），只有表3-3、3.5.1、3.3.5 保留全量。
4. **图只由训练集构建。** `edges.csv`、`triples.csv` 均只含训练集对（V9 3.3.6、
   4.4.4 防泄漏设计）；test/val 对不得进入图结构。3.1 的画像同理只统计训练图。
5. **`is_positive` / `is_hard_negative` 的正负口径**：`rating≥4` 为正（对应表3-1 的
   3.0/1.5 两档），`rating≤2` 为硬负（0.1 档），`rating=3` 不进三元组但**进边权与图**。
   三元组 = 每条正样本 × 4 个负样本，其中 `hard_ratio=0.5` 作为硬负替换上限；
   IS 实际硬负占比 14.3%、TH 21.3%、OP 14.1%、AJ 0%（AJ 无硬负池）——
   **论文写 1:4 时不要顺带声称「约一半是硬负」**。
6. **正文口径：画像用训练图，数据集统计用全量**（2026-11-25 统一，见 §二 分工表）。
   - 3.1 / 图3-1~3-5 / 3.3.4 / 3.5.3 / 3.5.4 / 3.6 / 4.3.1 用**训练集对**：
     评分 72.6/14.2/5.7/7.5、长尾 57.2/65.8/29.2/约48%、中位交互年龄 4.2 年、
     λ=0.1 时 <1e-6 占 99.39%。P130 已加口径声明句。
   - 表3-3、3.5.1、3.3.5 的复杂度常数用**全量对**：规模 50985/25848/412947、
     评分 72.3/13.7/5.8/8.2、稀疏度 99.97%。
   - 理由：图只由训练集构建（3.2/3.3.6），画像是给「模型看到的边」做诊断；
     数据集统计描述的是数据整体。两处数值差得不多，但口径必须各自说清。
7. **`T_now` 的取值**：`edges.csv` 与 `profile` 的 `lambda_sens` 都用**训练集**最大时间戳
   （V9 3.3.3 命题 1 说明这与全量最大时间戳等价），而 `stats.json` 的 `timestamp_max`
   是**全量**最大时间戳（IS 两者差约 1 天）。复算边权时以 `edge_weight.t_now` 为准。
8. **`tail_item_ratio` 阈值 = 10**，与 V9 3.3.4 的长尾定义 θ=10 一致。两个口径都已在
   `profile/IS.json` 中给出：`tail_train`（正文用，65.79%）与 `tail_full`（53.01%）。
9. **画像图与正文同口径（训练图）**。`figures/profile/IS_fig3-{1..5}_*.{svg,png}`
   （2026-11-25 重绘）：图3-1 训练集评分分布、图3-2 训练集每用户交互数（含 5/10/30
   分层线）、图3-3 训练集相邻间隔（含 Q1/中位/Q3）、图3-4 训练集商品长尾（标注
   前20%覆盖 57.2%、47.9% 覆盖 80%）、图3-5 训练集交互年龄下两档 λ 的边权数量级分布。
   旧命名（`IS_rating_dist` 等）已删除，绘图函数保留但不导出。
10. **`item_meta` 的字段覆盖（IS）**：title 100%、brand 99.9%、category 99.0%、
    **price 仅 74.7%**、features 非空 92.2%、description 非空 57.5%；TH price 63.3%、
    OP 66.8%。5.4.5 双层知识库与 3.3.4 语义锚点引用价格/描述时必须声明缺失率。
    AJ 的 `category`/`brand` 是天猫的 `cat_id`/`brand_id` **整数编码**，不是文本名，
    不能直接用于「类目兜底召回」与「品牌词典校验」的文本匹配。
11. **`behavior` 列是派生标签**，仅为兼容与 AJ 对齐；V9 3.3.1 已改为按 α_r 建模。
    不要在正文以 `behavior` 作论证依据。
