## 二、逐条证据

### P1：Amazon 数据集不存在多行为日志（致命）

**原稿表述**（4.1.2 段 233–237、4.1.1 段 228）：

> 「用户与商品之间存在购买（buy）、收藏（collect）、加购（cart）、点击（click）和
> 曝光（show）五类行为」「w(u,i) = Σ_{(u,i,b,t)∈Interactions(u,i)} α_b · exp(...)」
> 「同一用户-物品对可能有多次不同类型的交互记录」

**实际情况**：

| 事实 | 证据 |
|---|---|
| Amazon 2023 原始字段仅 4 个 | `data/raw_2023/IS_5core.csv.gz` 表头为 `user_id, parent_asin, rating, timestamp` |
| 每个用户-物品对只有一条评分记录 | `stats.json`: IS 的 `num_pairs == num_behavior_records == 412,947` |
| 所谓"行为"是从评分派生的伪标签 | `prepare_data.py` 的 `RATING_TO_BEHAVIOR`：5分→buy、4分→collect、3分→click、1~2分→show |
| cart 行为在三个 Amazon 数据集上记录数恒为 0 | `stats.json`: IS/TH/OP 的 `cart.count = 0` |

**结论**：Amazon 侧不存在"同一用户-物品对的多次不同类型交互"，式(4-1) 的求和号
在三个主数据集上恒为单项，属于无效符号；把它写成"多行为加权"是概念错位。
**AJ（Alibaba IJCAI15）确实有原生四类 `action_type`**，是全文中唯一真正支持
多行为叠加的数据集，但它是辅助验证集，不是主实验。

**修订方向**：把 4.1 节的建模对象明确为「**显式反馈强度**（rating→边权重标量）」，
删去多行为叙事；对 AJ 单独说明"多类行为可折算叠加为统一边权重"，作为边权重
框架的**兼容性验证**而非主设定。

### P2：`Industrial & Scientific` 是 B2C 零售类目，不是 B2B 场景（严重）

**原稿表述**（4.1.2 段 237、3.x 段 150/220）：

> 「在工业 B2B 采购场景中，购买行为代表已完成的采购决策……采购人员常将候选商品
> 收藏后上报审批」「符合工业资产商城 B2B 场景的实际接入方式」

**实际情况**：Amazon 的 `Industrial & Scientific` 类目是面向个人消费者、实验室、
中小企业与专业人士**零售**的工业与科学用品（实验器材、测量仪器、防护用品、耗材、
工具配件），其交易形态、用户角色、决策链条与国内大宗工业品批发/企业集采（B2B）
均不同。它本质是**电商零售（B2C）商品目录**，不是 B2B 平台。

**结论**：以"B2B 采购审批流程"论证"收藏权重高于加购"这一业务解释不成立——
数据集里既无审批信息，也无加购事件。

**修订方向**：明确说明 IS 是"**公开可得的、品类最贴近工业采购场景的 B2C 零售
代理数据集（proxy dataset）**"，研究结论的适用边界据此收窄；删去 B2B 措辞，
或改为"工业品采购场景"。论文中涉及业务语义的解释改挂在"显式评分分布"上
（可核对：IS 的 5 分占 72.3%、1~2 分占 8.2%），不再依赖不存在的业务流程。

### P3：λ=0.1 使 98.89% 的边权重退化至 1e-6 以下（致命）

**原稿表述**（4.1.2 段 235、5.8.1 段 498、表5-13 表格 21）：

> 「λ=0.1 为时间衰减率控制参数」「λ=0.1 的最优设定对应行为发生 1 天后权重保留
> e^{-0.1}≈0.90，7 天后保留 e^{-0.7}≈0.50」；表5-13 候选值为 0.01/0.05/0.1/0.2/0.5，
> 最优值 0.1。

**实测复算**（基于 IS 全部 412,947 条记录的真实时间戳，`T_now` 取数据集最大时间戳）：

| λ | 半衰期 | 权重 <1e-6 的记录占比 | 权重中位数 | 权重最小值 |
|---|---|---|---|---|
| 0.1 | 6.9 天 | **98.89%** | 0.0000 | 0 |
| 0.01 | 69.3 天 | 46.25% | 0.0000 | 1.1e-35 |
| **0.001** | **693 天（1.9 年）** | **0.00%** | **0.5714** | **2.4e-4** |

**根因**：IS 数据时间跨度为 **2001-07-04 至 2023-08-25（22.1 年）**，交互年龄
中位数为 **1,347 天（3.7 年）**。λ=0.1 的半衰期只有 6.9 天，相当于把
3 年以上的历史交互权重压到 e^{-109}≈0，等于丢弃 99% 的图结构。仅有 0.75%
的交互发生在"半衰期 x 20 = 138 天"以内。

**代码现状**：`prepare_data.py:67` 已设为 `DEFAULT_DECAY_LAMBDA = 0.001`，并在
注释中明确要求"论文 4.1.2 与表 5-21 的 λ 取值需同步改为 0.001"——即代码与论文
早已脱节，此次修订是把论文对齐到代码。

**修订方向**：

1. 4.1.2 式(4-1) 的 λ 改为 0.001，并补一句"半衰期 693 天，与工业品采购周期量级匹配"。
2. 表5-13（λ 敏感性）候选值改为 `0.0001/0.0005/0.001/0.005/0.01`，最优值 0.001。
3. 5.8.1 的衰减解释改为 1 年≈0.69、2 年≈0.48、5 年≈0.16，并**保留**一段
   "为何不用 λ=0.1"的说明（这是审稿人一定会问的点，主动交代更有利）。

> ⚠️ **注意**：λ 改动会使 5.8.1 的超参数敏感性实验数值需要**重跑**。本次仅做
> 文档口径对齐，表中 Recall@10 数值未改动，重跑后需以实测值替换。

### P4：规模与分布统计与实际数据不符（严重）

**原稿表5-1（表格 9）与 4.1.3（段 254）**：

| 项 | 原稿值 | 实测值 |
|---|---|---|
| IS 用户数 | 16,438 | **50,985** |
| IS 商品数 | 10,228 | **25,848** |
| IS 交互数 | 164,923 | **412,947** |
| IS 稀疏度 | 99.90% | **99.97%** |
| IS 平均交互/用户 | 10.0 | **8.10** |
| TH 用户/商品/交互 | 21,345 / 15,672 / 232,456 | **842,050 / 274,732 / 7,891,024** |
| OP 用户/商品/交互 | 18,763 / 12,457 / 198,341 | **223,308 / 77,551 / 1,800,878** |
| AJ 用户/商品/交互 | 24,389 / 12,847 / 432,786 | **420,027 / 574,926 / 30,875,771** |

原稿 5.1.1（段 407）还写「buy/collect/click/show 分别占 23.4%/18.2%/33.7%/24.7%」，
与实测 **72.3%/13.7%/5.8%/8.2%（按评分口径：5分/4分/3分/1~2分）** 相差甚远。
这组数字还直接支撑了"工业采购用户浏览少、决策准"的论断，结论方向需相应调整。

另：原稿 4.1.4（段 257）称「80% 的交互集中在 20% 的热门商品」，实测为
**56.5%**；长尾商品（<10 交互）占比实测 **53.0%**（原稿写"大量"，未给数值）。

**修订方向**：表5-1 全表按 `stats.json` 重填；4.1.3 的规模常数、4.1.4 的长尾
比例、5.1.1 的分布论述全部对齐实测值。

## 四、开放项（需人工决策或重跑）

1. **超参数敏感性实验需重跑**：表5-13 的 λ 候选网格从 `0.01~0.5` 改为
   `0.0001~0.01` 后，`最优 Recall@10` / `次优方案 Recall@10` 数值必须用新
   实验替换，当前保留的是原值，仅为占位。
2. **5.8.1 的衰减天数描述**：已按 λ=0.001 换算（1 年 0.69 / 2 年 0.48 / 5 年 0.16），
   若最终 λ 有变需同步。
3. **4.1.4 长尾正则的 8.3% 提升**：该数值无对应实验结果支撑（仓库尚无可训练代码），
   已在本次修订中**删除**，改为「加入该项后的性能变化见表5-11」。另需注意：
   - 4.1.4 原文「呈现明显的长尾特征」与 56.5% 这一偏低的集中度自相矛盾——
     IS 是四个数据集中长尾最弱的一个（TH 68.5%、OP 64.9%、AJ 74.9%，
     IS Gini=0.487），且覆盖 80% 交互需约 50% 的商品。已改为「中度长尾」。
   - 原文「嵌入向量质量较差，表现为离群点较多、与语义相近商品距离偏大」
     同样无实验支撑，已改为「可训练样本少、更易欠拟合」的设计动机表述。
   - 若需保留「长尾嵌入退化」这一论断，应在模型实现后补前置实验
     （长尾/头部商品嵌入的 L2 范数分布、kNN 平均余弦相似度）。
   - 5.7.1 表5-11 的「移除长尾正则 -3.2%」（整体 Recall 下降）与 4.1.4 原表述
     口径不同，修订后 4.1.4 已直接指向表5-11，口径统一。
4. **AJ 的行为权重映射**：AJ 有原生 `action_type`（0点击/1加购/2成交/3收藏），
   代码 `AJ_ACTION_TO_BEHAVIOR` 与表4-1 的评分权重是两套口径。建议在 4.1.2 或
   5.1.1 补一句映射表，明确 AJ 的边权重如何由 action_type 折算——否则读者会
   疑惑"同一套 α 如何同时服务评分和行为"。
5. **第3章线上系统与第4/5章实验的口径边界**：线上系统（user_interest 表、
   behavior_type 字段、五类行为埋点）是合理的工程设计，但需在全文至少一处
   （建议 3.4.2 或 5.1.1）显式声明"实验部分以 Amazon 评分数据集为代理，
   线上多行为日志为工程落地形态"，避免审稿人认为前后矛盾。当前已在段 191、
   312、615 三处加注，可考虑集中成一段。
6. **模型代码尚未实现**：仓库目前只有 `prepare_data.py`（数据预处理）与 mock
   后端，`docs/todolist.txt` 亦记录三阶段模型待实现。本报告只保证"论文 ↔ 数据"
   口径一致；"论文 ↔ 代码"的公式级一致性需在模型实现后再做一轮复核。
7. **1.1 节"单件均价数千至数十万元"**：Amazon IS 数据集无价格字段（meta 里
   的 price 混有 `from 24.87` 文本），该论断无法由数据集支撑，属行业背景陈述，
   建议补引用来源，否则删除或弱化。
