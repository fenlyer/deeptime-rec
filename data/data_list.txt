  【数据源根地址】
    Amazon 2023 官方：https://mcauleylab.ucsd.edu/public_datasets/data/amazon_2023/
    （McAuley Lab, UCSD 发布；即 docx 引用文献 [38] 对应的数据集）

  【与 docx 5.1.1 对齐的三条处理口径】
    · 5-core 过滤：保留交互次数 ≥5 的用户与商品
        → 直接使用官方 benchmark/5core/ 目录下已过滤好的文件，无需自行过滤
    · 留一法（LOO）划分：每位用户最后一条 → 测试，倒数第二条 → 验证，其余 → 训练
        → benchmark/5core/last_out/ 目录即为此口径
          （已实测验证：IS 的 train/valid/test 合计 412,947 条，与 rating_only
            全量完全一致；50,984/50,985 位用户的最后一条落在 test，
            倒数第二条落在 valid，仅 1 位用户因同一时间戳并列存在歧义）
    · 行为类型：Amazon 无原生加购事件，仅按评分推导 4 类（见第四节）
        → 与 docx 5.1.1 第二段"IS、TH、OP 三个数据集实际使用四类推导行为"一致

  【目录约定】
    data/raw_2023/              5-core 评分文件（建模用，必下）
    data/raw_2023/loo/          官方 LOO 划分（可选，用于与自建划分互校）
    data/raw_2023/raw/          原始评论与元数据（RAG 知识库、长尾正则化用）
    data/raw_aj/                AJ 天猫数据集

  【校验方式】
    下载后用字节数比对（见第五节脚本），并以 gzip -t 校验完整性。
    ⚠ 2026-11-11 复盘中曾出现 TH/OP 下载中途被截断的情况（gzip 报
      "unexpected end of file"），仅比对文件名不足以保证可用，必须跑 gzip -t。

────────────────────────────────────────────────────────────────────────────────
  四、行为类型推导规则（与 docx 表 4-1、5.1.1 对齐）
────────────────────────────────────────────────────────────────────────────────

  docx 表 4-1 定义的五类行为权重：

    行为     权重   依据
    buy      3.0    直接转化行为，最强偏好信号（基准值 ×3）
    collect  1.5    强意向但未转化（基准值 ×1.5）
    cart     1.2    加购后放弃率高，低于收藏
    click    1.0    标准基准行为
    show     0.1    极低价值噪声，仅补冷启动连通性

  Amazon 推导规则（docx 5.1.1 原文）：
    rating=5   → buy      (3.0)
    rating=4   → collect  (1.5)
    rating=3   → click    (1.0)
    rating=1/2 → show     (0.1)
    ※ Amazon 无原生 cart，权重 1.2 仅用于 AJ 与线上环境（docx 5.1.1 已说明）

  ⚠ IS 实测行为分布与 docx 5.1.1 末段严重不符：

    ┌──────────┬───────────────┬──────────────┬──────────┐
    │ 行为     │ docx 5.1.1    │ IS 实测      │ 偏差     │
    ├──────────┼───────────────┼──────────────┼──────────┤
    │ buy      │ 23.4%         │ 72.3%        │ +48.9pp  │
    │ collect  │ 18.2%         │ 13.7%        │ -4.5pp   │
    │ click    │ 33.7%         │ 5.8%         │ -27.9pp  │
    │ show     │ 24.7%         │ 8.2%         │ -16.5pp  │
    └──────────┴───────────────┴──────────────┴──────────┘
    实测依据：rating=5 有 298,567 条，rating=4 有 56,718 条，rating=3 有 23,792 条，
    rating=1/2 分别 20,970 / 12,900 条，合计 412,947 条。

    docx 原文"购买行为占比相对消费品数据集更高"这一定性结论仍然成立（72.3%
    确实很高），但"click(33.7%) 高于 buy(23.4%)"在 Amazon 的评分分布下不可能
    出现（Amazon 评分极度右偏，5 分占 6~75%），这组数字必须替换。

    ⚠ 同时需要正视一个建模后果：buy 占 72.3% 意味着 α_b 在 Amazon 上几乎退化为
      常数，行为加权消融（docx 表 5-11 中"去除行为权重"约 -12.2%）在 IS 上
      难以做出与其他数据一致的效果。可选路径：
        A. 改用 verified_purchase + helpful_vote + rating 三维度构造更均衡的
           四类分布（需 IS_reviews.jsonl.gz，属"本文提出的推导规则"，须在正文
           显式声明）；
        B. 用 rating 强度作连续权重（需重写式 4-1 与表 4-1）；
        C. 行为加权实验只放在 AJ 上做，Amazon 侧只用 IS 做主实验、不宣称加权增益。
      该决策会影响论文第 4、5 章，须在跑实验前定稿。

  ── 5.3 统计脚本（回填 1.5 / 2.5 / 3.3 三张表）───────────────────────

    cd data/raw_2023
    python3 -I - <<'PY'
    import gzip, csv, sys
    from collections import Counter
    from datetime import datetime
    for name in ["IS_5core.csv.gz", "TH_5core.csv.gz", "OP_5core.csv.gz"]:
        uc, ic, rated = Counter(), Counter(), Counter()
        n = 0; ts_min = ts_max = None; pairs = set(); dup = 0
        with gzip.open(name, "rt") as fh:
            r = csv.reader(fh); next(r)
            for row in r:
                if len(row) < 4: continue
                k = (row[0], row[1])
                if k in pairs: dup += 1
                pairs.add(k)
                uc[row[0]] += 1; ic[row[1]] += 1
                rated[int(float(row[2]))] += 1
                t = int(row[3]); n += 1
                ts_min = t if ts_min is None else min(ts_min, t)
                ts_max = t if ts_max is None else max(ts_max, t)
        sp = 1 - n / (len(uc) * len(ic))
        buy, coll, clk = rated[5], rated[4], rated[3]
        show = rated[1] + rated[2]
        print(f"== {name}")
        print(f"   用户={len(uc):,} 商品={len(ic):,} 交互={n:,} 重复对={dup}")
        print(f"   稀疏度={sp*100:.4f}% 平均交互/用户={n/len(uc):.2f}")
        print(f"   时间跨度={datetime.fromtimestamp(ts_min/1000):%Y-%m}"
              f" ~ {datetime.fromtimestamp(ts_max/1000):%Y-%m}")
        print(f"   buy={buy/n*100:.1f}% collect={coll/n*100:.1f}% "
              f"click={clk/n*100:.1f}% show={show/n*100:.1f}%")
        print(f"   最小用户交互={min(uc.values())} 最小商品交互={min(ic.values())}")
    PY
