## 三、`prepare_data.py` 必须修复的三个 Bug

### Bug 1：meta 文件无法读取（致命）

`prepare_data.py:51-69` 的 `load_json_gz` 函数用 `json.loads` 解析所有行。SNAP v1 的 meta 文件是 Python dict 字面量（单引号 `'asin': '0736513299'`），不是合法 JSON，**所有 meta 记录都会被跳过**且只输出前 5 行警告。

**修复方案**：

```python
import ast

def load_json_gz(filepath: Path) -> list[dict]:
    records = []
    fail_count = 0
    with gzip.open(filepath, "rt", encoding="utf-8") as f:
        for line_no, line in enumerate(f, 1):
            line = line.strip()
            if not line:
                continue
            try:
                records.append(json.loads(line))
            except json.JSONDecodeError:
                try:
                    records.append(ast.literal_eval(line))  # meta 文件走这里
                except Exception:
                    fail_count += 1
    if not records:
        raise RuntimeError(f"{filepath} 解析出 0 条记录，请检查文件格式")
    if fail_count > 0:
        log(f"跳过 {fail_count} 条无效记录", "WARN")
    return records
```

### Bug 3：LOO 划分与论文描述不一致

论文写"留一法（Leave-One-Out, LOO）划分：每位用户的最后一条交互作为测试样本，倒数第二条作为验证样本"。但 `prepare_data.py:185-226` 的 `temporal_split` 函数按 `val_ratio=10%, test_ratio=10%` 做比例划分，不是 LOO。

**修复方案**：

```python
def temporal_split_loo(df: pd.DataFrame) -> dict:
    """留一法时序划分：最后一条→测试，倒数第二条→验证，其余→训练"""
    log("LOO 时序划分...")
    df_sorted = df.sort_values("timestamp")
    train_records, val_records, test_records = [], [], []
    
    for uid, group in df_sorted.groupby("user_id"):
        n = len(group)
        if n < 3:
            # 交互不足 3 条的用户：最后一条测试，其余训练
            train_records.append(group.iloc[:-1])
            test_records.append(group.iloc[-1:])
            continue
        # 最后一条→测试
        test_records.append(group.iloc[-1:])
        # 倒数第二条→验证
        val_records.append(group.iloc[-2:-1])
        # 其余→训练
        train_records.append(group.iloc[:-2])
    
    result = {
        "train": pd.concat(train_records, ignore_index=True),
        "val": pd.concat(val_records, ignore_index=True),
        "test": pd.concat(test_records, ignore_index=True),
    }
    for split, data in result.items():
        log(f"  {split}: {len(data):,} 条 ({len(data)/len(df)*100:.1f}%)")
    return result
```

## 四、行为加权方案：当前映射的问题与替代方案

### 4.1 问题

论文的 rating→行为映射（5→buy, 4→collect, 3→click, 1-2→show）在真实 Amazon 2023 IS 5-core 上产生：

| 行为 | 占比 |
|---|---|
| buy | **72.3%** |
| collect | 13.7% |
| click | 5.8% |
| show | 8.2% |

**问题**：buy 占 72%，行为加权退化为近似常数，`α_b` 的差异几乎体现不出来。消融实验（"去除行为权重"）的效果差异会极小，缺乏说服力。

### 4.2 替代方案 A（推荐）：verified + helpful + rating 三维度组合

利用 Amazon 2023 review 数据中的 `verified_purchase` 和 `helpful_vote` 字段构造更均衡的行为分布：

| 条件 | 行为 | 预期占比 |
|---|---|---|
| verified=True & rating=5 & helpful>0 | buy | ~25% |
| verified=True & rating≥4 | collect | ~25% |
| verified=False & rating≥4 | click | ~25% |
| rating≤3 | show | ~25% |

**优势**：四分布更均衡，消融实验能做出差异。  
**代价**：需要在论文里明确说明这是"本文提出的推导规则"，而非数据集原生行为。

### 4.3 替代方案 B：直接用 rating 强度作为连续权重

不做离散行为分类，直接用 rating 作为连续权重：

```
w(u,i) = rating × exp(-λ · Δt/T)
```

**优势**：不需要推导行为类型，避免分布不均问题。  
**代价**：论文第四章的式(4-1)和表 4-1 需要重写，消融实验设计也要调整。

### 4.4 替代方案 C：主数据集换成原生多行为数据

放弃 Amazon 做行为加权实验，改用 Tmall (IJCAI 2019) 或 Alibaba IJCAI15（论文里已有 AJ）。Amazon 2023 只用于 LLM 属性蒸馏实验。
